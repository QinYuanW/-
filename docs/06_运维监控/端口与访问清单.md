# 物联网 PaaS 端口与服务访问清单

> 适用范围：本地/开发机一键启动的整套栈（Docker + 后端 + MySQL）
> 更新日期：2026-09-10
> 一句话：**都在本机 localhost，浏览器能开的就三个——Grafana(3000)、Prometheus(9090)、EMQX(18083)。**

---

## 一、端口总表

| 端口 | 服务 | 容器/进程 | 用途 | 访问地址 |
|:---:|------|-----------|------|---------|
| 1883 | EMQX MQTT | emqx(Docker) | 设备接入协议口 | `1883`（明文）/ `8883`（TLS） |
| 18083 | EMQX Dashboard | emqx(Docker) | EMQX 管理后台 | http://localhost:18083 |
| 3000 | Grafana | grafana(Docker) | **监控大盘** | http://localhost:3000 |
| 9090 | Prometheus | prometheus(Docker) | 指标存储 & 查询 | http://localhost:9090 |
| 9093 | Alertmanager | alertmanager(Docker) | 告警管理 | http://localhost:9093 |
| 6379 | Redis | redis(Docker) | 缓存（设备在线/鉴权/ID 映射） | localhost:6379 |
| 3306 | MySQL | MySQL57(Windows 服务) | 业务库 `iot_platform` | localhost:3306 |
| 8080 | SpringBoot 后端 | java(本机) | 业务 API / 指标 / 健康 | http://localhost:8080 |

> 容器内还有 `8083-8084`(EMQX 内部)、`4370`、`5369` 等端口映射，业务上用不到，忽略即可。

## 二、三块关键人间入口

### 1️⃣ Grafana（最常用，直接看大盘）
- 地址：**http://localhost:3000**
- 账号：`admin`，密码：`admin`（默认；首次登录会提示改密，可点 Skip 跳过）
- 若忘记密码：`docker exec -it grafana grafana cli admin reset-admin-password 新密码`
  - ⚠️ Grafana 11 已**移除** `grafana-cli` 单命令形式，必须写成 `grafana cli`（中间有空格），否则报 `executable file not found`
- ⚠️ **Grafana 数据未持久化**：compose 未挂载 `/var/lib/grafana`（顶层 volumes 只有 emqx/redis/kafka），`docker compose down/up` 触发 recreate 后，改过的密码、自建大盘、告警静默全部归零并回到 `admin/admin`。要避免就补 `grafana_data:/var/lib/grafana`
- 大盘：菜单 **Dashboards → browse**，选 **IoT Platform Main**（含运行概览 / JVM / 接口 QPS·耗时 / 线程池 / EMQX 接入层，带 URI 筛选变量）

### 2️⃣ Prometheus（看指标原始趋势 / 手写 PromQL）
- 地址：**http://localhost:9090**
- 菜单 **Status → Targets** 看各抓取目标是否 UP
- **All metrics** 下拉挑指标，或用 Graph 手写 PromQL
- 常用指标：
  - `iot_telemetry_queue_pending` — 遥测异步队列水位（瓶颈关键）
  - `iot_telemetry_process_duration_seconds` — 上报→入库链路耗时（P95/P99）
  - `iot_telemetry_process_failures_total` — 入库失败计数
  - `jvm_threads_live_threads` — JVM 存活线程
  - `emqx_connections_count` / `emqx_messages_received` — EMQX 连接 / 报文
  - `scrape_duration_seconds` / `up` — 抓取健康

### 3️⃣ EMQX Dashboard（看设备接入 / MQTT 消息）
- 地址：**http://localhost:18083**
- 账号：`admin`，密码：`public`
- 重点看：**Connections**(连接数)、**Topics/消息速率**，以及 **Rule Engine**(确认 `forward_telemetry_rule`、`forward_ack_rule` 是否 enable)

## 三、后端 API / 指标直达

| 用途 | 地址 |
|------|------|
| 健康检查（一键看组件） | http://localhost:8080/actuator/health |
| Prometheus 指标裸端点 | http://localhost:8080/actuator/prometheus |
| 业务接口 | http://localhost:8080/api/v1/**（需 JWT，除登录与 EMQX 回调） |

`/actuator/health` 会返回 **EMQX / db / redis / diskSpace / ping** 各组件 UP/DOWN，是最快的探活手段。

## 五、常见操作

| 想做的事 | 怎么做 |
|---------|--------|
| 启动/查看整套栈 | `docker compose up -d` / `docker ps` |
| 看后端日志 | 后端由你在 IDEA 中运行，日志在 IDEA console |
| 查 MySQL 状态 | Windows 服务 `MySQL57`；`net start MySQL57`（需管理员） |
| 重跑压测 | `python tmp/test_storm_telemetry_v2.py --file tmp/flood_devices.txt --count 1000 --interval 0.5 --duration 60` |
| 看压测结论 | `docs/05_压测报告/MySQL时序瓶颈分析报告.md` |
