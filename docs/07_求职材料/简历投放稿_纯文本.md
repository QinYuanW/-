## 二、开发岗

```
物联网 PaaS 云平台    独立全栈开发    2025.06–2025.09
独立完成一套面向设备的物联网 PaaS 平台，覆盖设备接入鉴权、高可靠遥测链路、物模型驱动的前端控制台与可观测体系。

• 设备接入与指令闭环：基于 EMQX 三元组鉴权与认证回调打通 MQTT 上下行链路，落地指令状态机（待下发 → 已下发 → 已执行/失败/超时）与 ACK 幂等，重复与乱序回报不覆盖终态；将设备与产品启停统一收敛到认证、遥测、事件、指令四条入站链路，实现停用后即时拦截。

• 遥测链路重构：原进程内队列直推在压测中打满即静默丢弃（交付率跌至 30%，且监控完全无感知），改为 EMQX → Kafka → 消费者组解耦，以幂等唯一键实现至少一次语义下的写入去重，用失败分级 + 非阻塞重试阶梯 + 死信队列根治"失败记录被后续提交越过"的静默丢失；实测突发 5000 条与进程强杀重启场景均零丢失。

• 压测定位真瓶颈：搭建压测与指标观测体系主动把系统打到瓶颈，优化写入路径后稳态吞吐提升 2.5 倍（约 98 → 248 msg/s）；再以链路耗时埋点、线程栈与数据库状态指标证明瓶颈在消费侧而非数据库（单条 13.6 ms，数据库侧几乎空闲），据此判断引入时序库"收益不抵复杂度"并终止迁移。

• 数据模型与安全加固：设计 11 张核心表并将遥测数据按月分区；设备密钥以 AES-256-GCM 密文入库（旧明文首次认证自动转密、零停机迁移），MQTT 接入启用 TLS（8883，自签带 SAN 证书 + 目录挂载持久化）。

• 前端控制台与可观测：以 Vue 3 + Vite 构建控制台，页面与控件 100% 由物模型（TSL）驱动，新增传感器仅需编辑物模型、渲染代码零改动；实时数据由 5 秒轮询改为 WebSocket 推送，端到端延迟降至 22 ms；以自定义埋点接入 Prometheus + Grafana（18 面板），修复 4 块"面板存在但永远无数据"的伪正常状态。
```
