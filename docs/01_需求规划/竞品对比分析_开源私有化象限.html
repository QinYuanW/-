需求文档 §6 把竞品圈在了 OneNET / 阿里云 / 腾讯云 / 华为云 —— 那是"公有云大厂"象限。 但汤园这次问的三家，全在另一个象限：开源 + 可私有化 + 轻量。 那才是我们真正会被拿去做 A/B 对比的对手。这份看板把两个象限分开摆。

一、三家不是一个物种：物联网平台的三个"海拔"看似都在做 IoT 平台，其实生态位从水平到垂直完全错开

巴法云 · bemfa
山脚的缆车 · 通信管道

只负责"把设备连上"，不做设备管理。MQTT/TCP 双向中继，三步接入，免费 10 设备 / 10 主题。

本质：免运维的 MQTT 消息中继
商业模式：免费额度 + ¥9/设备/月起
用户：创客 / 学生 / 毕设原型 / DIY
短板：无物模型、无规则引擎、无多租户
FastBee · 蜂信物联
山腰的全包民宿 · 开箱即用交付

单体 SpringBoot + Vue，一条龙从小程序到组态大屏。已服务 200+ 企业，主打"快上线、低成本、能自己改"。

本质：一体化交付平台
商业模式：开源（个人学习）+ 商业永久授权
用户：中小企业 / 个人开发者
短板：规则引擎弱、仪表盘不如 ThingsBoard 灵活
JetLinks
山顶的自建地基 · 企业级技术底座

全响应式 Java17 + WebFlux + Reactor，统一物模型 + 可视化规则设计器 + 三维数据权限，面向"自建物联中台"。

本质：企业级 IoT 技术底座
商业模式：社区版 + 企业版 + SaaS + Edge
用户：大集团 / 有完整研发团队的团队
短板：只给底座，看板/告警/小程序要自己开发
一句话记住三者的区别：巴法云卖"连得上"，FastBee 卖"开得快"，JetLinks 卖"撑得住"。 三家的付费理由不同，说明它们解决的是三种不同的焦虑 —— 这也决定了它们的功能取舍。

五、五条关键洞察面试 / 答辩直接可用

  1. 真正的对手不是大厂云，是 FastBee 和 JetLinks。需求文档 §6 对比的是 OneNET/阿里/腾讯/华为（公有云象限），但"开源可私有化"象限里，FastBee/JetLinks 才是抢同一批客群的直接替代品。答辩时如果被问"市面上已经有 FastBee 了你还做什么"，答案要在这一条上。
  2. 不要在功能覆盖度上硬碰。FastBee 有 GB28181 视频 + Uniapp 多端 + 组态大屏，JetLinks 有响应式集群 + AI 视觉 + 三维权限。这两家是团队多年沉淀，单人毕设堆功能只会样样稀松。范围声明里"有意暂缓"是战略选择，不是能力不足 —— 这句话必须说出口。
  3. 我们唯一能赢的护城河是"证据链"。JetLinks 是空白底座（怎么用是你的事），FastBee 是黑盒交付（怎么做到的不告诉你），巴法云根本不做平台层。而我们能拿出"发现瓶颈 → 量化 → 选型 → 验证"的完整链路，这是面试官真正想听的。
  4. 最短的差距补齐路径：E2 → E6 → E3。E2 WebSocket 是三家的标配而我们是空白，形态上最刺眼；E6 统计接口是 D3/D5 报告里"查询 RT"的唯一基线；E3 规则引擎补完才配叫"平台"而不是"管道"。三者有严格先后依赖，不要并行。
  5. 三家的商业模式值得抄一句。巴法云证明"最后一公里连通性"本身就是生意；FastBee 证明"完整 + 私有化 + 中文文档"能卖给中小企业；JetLinks 证明"帮你摆脱厂商锁定"能卖给大厂。毕设不需要变现，但答辩里能讲清"这个平台该卖给谁、凭什么收费"，是产品思维的加分项。
